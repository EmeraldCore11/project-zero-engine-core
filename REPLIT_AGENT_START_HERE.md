# Replit Agent — Start Here

Before making changes, read the authoritative Project Zero documents in this repository and the linked architecture repositories.

## Mandatory operating rules

1. Do not assume that a summary is a substitute for an approved source document.
2. If a required TDD, specification, decision, or approval is absent, report it as missing and ask for it. Never claim to have read a document that was not supplied.
3. Preserve the original TDD requirements unless an explicit approved decision changes them.
4. Record conflicts rather than silently choosing one interpretation.
5. Product approval does not authorize implementation. Do not implement features until the user explicitly authorizes the relevant stage and scope.
6. Do not change dependencies, packages, services, infrastructure, schemas, or code merely because a document mentions them.
7. Keep Project Zero separate from unrelated projects.
8. Prefer small, reviewable changes and explain their purpose, affected files, risks, and verification steps.

## Before any implementation

Produce a concise readiness report containing:
- documents actually available and read;
- unresolved requirements or conflicts;
- architecture boundary affected;
- proposed files and changes;
- dependencies or external services required;
- tests and acceptance criteria;
- explicit approval needed before proceeding.

## Source of truth

The approved TDD, Master TDD, Master Specification Index, specification library, MSI, and decision register take precedence over informal summaries. When these documents are not present, stop and request them.
